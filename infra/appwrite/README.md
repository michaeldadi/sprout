# Sprout Appwrite infrastructure

One Terraform root manages any Sprout Appwrite environment. The selected
`environments/<name>.tfvars` file supplies project and resource IDs; the
Terraform workspace with the same name holds that environment's state. The
workspace guard fails a plan if the names differ. Add another environment by
adding one data file, without copying resource code.

The current files record the **existing** production and staging Appwrite Cloud
projects as read on 2026-11-09. The `import` blocks adopt those resource IDs
into state. They do not authorize replacement or creation. Both projects have
an empty TablesDB database, a document bucket, and a landing site. Production
also has five existing template functions and one Terraform project API key.
Function and site deployments generated by Appwrite from Git are runtime
artifacts; the Git linkage and build configuration are modeled here. Their
latest deployments were failing at inventory time, and this configuration does
not make them work.

## Use

1. Create an encrypted HCP Terraform remote backend configuration at
   `backend.hcl` using `backend.hcl.example`. The workspace prefix can be
   shared; each environment uses its own workspace. Authenticate to HCP
   Terraform without putting tokens in this repository.
2. Supply `APPWRITE_API_KEY` for the selected Appwrite project and
   `APPWRITE_ORGANIZATION_API_KEY` for project and key administration through a
   secret manager or local environment. Never commit either credential or a
   Terraform state file. The official provider cannot create a project API key:
   bootstrap a scoped key in Appwrite, then add and import its metadata.
   The staging key was bootstrapped on 2026-11-09 and its generated ID and
   28 scopes are recorded in `environments/staging.tfvars`.
3. Run `./tf.sh staging validate` or `./tf.sh production validate` for
   formatting and configuration syntax. This does not check live drift or
   environment values. Run `./tf.sh <environment> plan` to preview import and
   drift. It writes a private `.plans/<environment>.tfplan` containing sensitive
   values. Inspect the full plan and its SHA-256, then run
   `./tf.sh <environment> apply` to apply that saved plan. Delete the local plan
   after use. The first apply imports existing resources into that workspace's
   remote state.

The production Speech recognition function has a credential-shaped variable.
Its value is deliberately absent from committed configuration. Supply
`TF_VAR_function_secret_values` as a JSON map with key
`speech_huggingface_token` from a secret manager when planning production.
The provider's write-only `value_wo` field keeps the value out of state.
Several other template function variables are currently blank in Appwrite;
their blank configuration is recorded literally.

Mobile builds select their Appwrite project independently of Terraform state.
Set `SPROUT_APPWRITE_ENDPOINT` and `SPROUT_APPWRITE_PROJECT_ID` for the selected
environment. Android reads these public identifiers and
`SPROUT_GOOGLE_WEB_CLIENT_ID` from `apps/.env.local` at build time. iOS reads
the same three build settings through `Info.plist`; pass them through the
selected Xcode configuration or CI. The Google web client ID must be the
same value declared in `native_oauth.google.native_client_ids` for that
environment. Keep provider secrets out of mobile builds. Until the Appwrite
financial data path is in place, existing social auth UI remains fail-closed.

## Coverage and gates

The official `appwrite/appwrite` provider is pinned at 2.3.0. This root
defines the existing projects, TablesDB databases, storage buckets, sites and
site variables, production functions and variables, and the production
project API key. No TablesDB tables, rows, users, teams, messaging resources,
or webhooks existed in either project at inventory time. Appwrite-generated
deployment and preview domains are outputs of deployments, not custom domains.

Provider 2.3.0 does **not** model the existing iOS/Android platform
registrations, OAuth/auth method settings, or the bucket `stripMetadata`
setting. The `settings.tf` bridge declares and reads those settings during
every plan, then applies reviewed differences through Appwrite's API with a
readback. It never deletes remote resources. Production currently strips
document metadata; staging does not. Native Apple sign-in uses the exact
case-sensitive iOS bundle ID, while Google uses the current Android web OAuth
client ID as its Appwrite audience. Verify that web client in Google Cloud
and configure the same server client ID in the iOS build before activating
Google sign-in.

The landing sites point to `./apps/web`, which is absent from this checkout.
No site or function deployment is imported or activated by this configuration.

On 2026-11-09, the staging Terraform project key was bootstrapped in Appwrite.
Seven existing staging resources were imported into the `sprout-appwrite-staging`
HCP state: the project, project key, TablesDB database, site, and three site
variables. The subsequent apply recorded 56 Terraform tracking entries,
hydrated the site and public variable resources, and corrected the iOS
platform bundle ID and Apple/Google native client IDs. The OAuth providers
remain disabled. Concurrent Apple and Google PATCH requests initially caused
Apple's readback to fail; a serial recovery apply completed, and a fresh
`terraform plan -detailed-exitcode` returned 0 (no changes). `tf.sh apply`
now uses `-parallelism=1` to avoid this race. Both temporary four-scope
organization keys were revoked and their local secrets and plan files removed.

OAuth refuses to mint a key that outlives its grant. The Sprout Finance console
did not show the documented Partners key section, so future local plans need a
newly minted short-lived organization key or another supported organization
credential. Production has no Terraform state yet and its existing project key
secret is unavailable locally. Bootstrap a scoped production project key or
recover the existing secret before its state imports. The production function
secret value must also be supplied outside source control for a full plan.
